# OwnForm 开发与发布流程（会话必读）

> 本文件是项目的"操作手册"。任何新会话继续开发时，先读本文件了解：
> 项目现状、版本规则、发版流程、授权体系架构、常见坑。

## 项目定位

自托管表单收集与私域引流系统，**商业授权销售**模式：
- 客户拿源码部署到自己服务器，凭授权码激活
- 授权中心（我们控制）负责授权验证与在线更新分发

- `version/0.0.1/`：基线安装包 + 授权中心包（历史）
- `version/0.0.2/`：当前发布包（宝塔部署包 + 更新包）
- 本地测试授权中心：`http://127.0.0.1:8031`（admin / admin123456，仅测试用）

## 目录结构（关键部分）

```
app/                  ThinkPHP 8 后端（controller/logic/middleware/command）
admin-src/            管理端 Vue3 源码（pnpm build 输出到 public/admin）
license-server/       授权中心单文件 PHP（独立部署到我们服务器，gitignore）
public/static/        访客端（fill 表单页 / page 内容页 / vendor 前端库）
docs/                 系统介绍、产品介绍、界面截图
scripts/              打包脚本、自检脚本、伪静态样例、部署说明
version/<版本>/       发布包产物（gitignore，不进仓库）
config/version.php    版本号唯一真源
config/db_local.php   数据库配置（安装器生成，gitignore）
```

## 授权体系架构（重要）

```
客户系统(OwnForm) ──激活/心跳/检查更新──> 授权中心(license-server)
     │                                        │
     │  安装向导第2步填授权码+服务器地址          │  授权码：域名绑定/到期/封禁
     │  每日静默心跳（挂数据概览）               │  更新包：zip+版本号+SHA256
     │  30天宽限期 → 超期只读(4009/4031)        │  离线激活码：服务器不可达时兜底
```

- 客户端逻辑：`app/logic/License.php`（激活/心跳/checkUpdate/applyUpdate）
- 授权端点：`UpdateApi.php`（status/activate/verify/check/apply）
- 锁定机制：`AdminAuth` 中间件拦截后台写操作（4031）、`FillApi/PayApi` 拦截访客提交（4009）
- **运行状态语义**：有 token 即 ok；心跳断联超 30 天才 locked；未配置服务器地址 = ok（兼容老用户）
- **授权服务器独立部署在我们服务器**，`license-server/` 目录在 .gitignore 中（勿提交、勿打进客户包）

## 版本与发布规则

1. **版本号**：开发完成 → `config/version.php` 升版（如 0.0.2 → 0.0.3），
   同步更新 `scripts/宝塔部署说明.txt` 的版本号
2. **增量 SQL**：有数据库变更时新建 `scripts/upgrade-<新版本>.sql`（幂等可重复执行），
   并同步更新 `install/schema.sql`（新装用户）
3. **两种包**：`build-release.sh` 自动产出
   - `宝塔部署包.zip`：新客户全量安装
   - `更新包.zip`：老客户覆盖升级（客户在"关于系统"页一键热更新）
4. **授权中心上传**：更新包 zip 单独上传到授权中心（客户热更新拉取用）
5. **更新日志**：写进部署说明 + docs/（新版本要点章节）

## 发版标准流程（用户说"打包"时执行）

```bash
# 1) 发版前自检（六项：语法/路由/构建一致性/敏感文件/schema/版本一致）
./scripts/pre-release-check.sh

# 2) 前端构建（源码有改动时）
cd admin-src && pnpm build && cd ..

# 3) 打包（自动产出宝塔部署包+更新包到 version/<版本>/）
./scripts/build-release.sh <版本号>

# 4) 授权中心上传更新包（或提示用户手动上传）
#    本地测试：curl -F "version=<版本>" -F "pkg=@version/<版本>/ownform-<版本>-更新包.zip" \
#      http://127.0.0.1:8031/admin/api/package/upload

# 5) git 提交推送（license-server/ 在 gitignore 中，勿强制加入）
git add -A && git commit && git push
```

## 发版前自检脚本说明

`scripts/pre-release-check.sh` 六项检查（任何一项失败禁止打包）：
1. PHP 语法（app/config/route 全部文件）
2. 路由 → 控制器方法存在性
3. 前端构建产物与源码一致性（防"改了没生效"）
4. 敏感文件不入库
5. schema.sql 与实际库结构比对
6. 版本文件与文档一致

## 历史教训（务必避免）

1. **修复后必须验证落盘**：PDO 命名空间修复曾被后续操作覆盖丢失，
   导致客户热更新失败——所以有了 pre-release-check 的构建一致性检查
2. **模板引用完整性**：Vue 模板引用的函数必须在 script 定义（genToken 事故），
   改完组件后用 `node --check` 或浏览器实测
3. **未登录页面请求要 302**：授权中心 needAdmin 对页面请求返回 401 JSON 会导致
   浏览器渲染缓存页 + B is not defined 假象——页面请求 302 到登录页，AJAX 才返回 401
4. **条件渲染**：授权中心多页面共用单文件，每个 `echo layout()` 必须有对应的
   if 条件 + exit（否则所有 URL 都显示同一个页面）
5. **zip 更新用 -d 或先删**：`zip` 对已存在文件是合并语义，重复打包会累积旧 chunk
6. **PHP 内置服务器测试授权中心时**：创建 `data/base.php` 指定前缀
   （`<?php return "/center";`），nginx 常规部署可自动推导
